# tvision-rs 0.7 upgrade + highlighting simplification

Date: 2026-07-03
Branch: `feat/shuttle-widget`
Status: approved design, ready for implementation plan

## Problem

edaptor hand-rolls its focus-driven highlighting because the framework
(tvision-rs 0.5) could not express "this pane's content recedes when the pane
loses focus". Three workarounds resulted:

1. **`leaf.rs`** mirrors the pane's `focused` onto the embedded list's `active`
   flag each draw (`list.state_mut().state.active = focused`), because the 0.5
   `ListViewer` keyed its bright palette on `selected && active` (always true for
   a nested list), so it never dimmed on focus loss.
2. **`field_label.rs`** — a custom form-pane label widget — carries its own
   `focused` field that `FormPane` pushes onto every label on every draw, so the
   labels can pick a bright/dim role.
3. **`tree.rs`** and **`form.rs`** hand-fill their whole pane extent with a role
   chosen from `self.group.state().state.focused`, because a `Group` paints no
   background of its own.

tvision-rs 0.7 removes the need for all three:

- **v0.6** added `DrawCtx::owner_active()` — each `Group::draw` fans its own
  `focused` to its children; a content widget reads it for its surface and its
  own `state.focused` for its highlight. `ListViewer`, `Outline` and `InputLine`
  now key on `owner_active` natively (fixing 1, and making the tree outline /
  form input cells dim automatically). v0.6 also renamed the focus-aware roles.
- **v0.7** added `Group::set_surface(normal, inactive)` — a group paints its own
  extent (keyed on its own `focused`) before drawing children (fixing 3).

## Goal

Upgrade to `tvision-rs = "0.7"` and delete edaptor's manual focus-drawing,
letting the framework drive it. After this change, no edaptor pane reads
`self.group.focused` (or mirrors focus onto a child's `active`) for surface
selection.

## Confirmed API facts (from the 0.7.0 crate source)

- `DrawCtx::owner_active(&self) -> bool` (`src/view/context.rs`); set by
  `Group::draw` via `set_owner_active`. `Group::draw` computes
  `owner_active = self.st.state.focused` and fans it to every child.
- `Group::set_surface(&mut self, normal: Role, inactive: Role)` and
  `Group::clear_surface(&mut self)` (`src/view/group.rs`); backed by
  `surface: Option<(Role, Role)>` (default `None` → paints nothing, unchanged
  `TGroup` behaviour). When set, `Group::draw` fills its extent with
  `if focused { normal } else { inactive }` **before** drawing children.
- Renamed roles (v0.6, unchanged in 0.7): `ListNormalActive` → `ListNormal`,
  `ListNormalInactive` → `ListInactive`, `OutlineNormalInactive` →
  `OutlineInactive`, `InputPassive` → `InputInactive`.

## The two-axis model (why this is correct)

- A **content widget inside a pane group** reads `ctx.owner_active()` — that is
  the *owning group's* `focused`, i.e. "is my pane the active pane". Correct for
  the leaf list and the form's `FieldLabel`s.
- A **group's own background** keys on its own `self.st.state.focused` — which is
  what `set_surface` reads internally. Correct for the tree/form pane chrome.
- At a pane's *own* draw level, `ctx.owner_active()` is the *parent* (window)
  focus — effectively always true — which is exactly why the manual fill could
  not use it and had to read `self.group.focused`. `set_surface` moves that read
  into the framework.

## Design

### 1. Dependency bump + role renames

`Cargo.toml`: `tvision-rs = "0.7"`. Apply the four role renames everywhere edaptor
references them — 32 references across `theme.rs`, `tree.rs`, `leaf.rs`,
`form.rs`, `field_label.rs`, `scroll_group.rs`, plus their tests:

- `ListNormalActive` → `ListNormal`
- `ListNormalInactive` → `ListInactive`
- `OutlineNormalInactive` → `OutlineInactive`
- `InputPassive` → `InputInactive`

edaptor's theme deliberately *dims* the `*Inactive` roles (that is how unfocused
panes recede), so `theme.rs`'s role→colour table keeps its dimmed colours — they
just move onto the renamed role keys. No colour value changes.

### 2. Delete the `leaf.rs` active-mirror hack

Remove the `list.state_mut().state.active = focused` block and its explanatory
comment in `LeafPane::draw` (around `leaf.rs:208-220`). The 0.6/0.7 `ListViewer`
keys its surface on `owner_active` (fanned from the leaf group's focus) and its
current-row highlight on its own `state.focused` — both already track pane focus.
The leaf dims natively. `LeafPane` gets no `set_surface` (it hand-fills no
background today; the list tiles the pane).

### 3. `field_label.rs`: adopt `owner_active`, drop the focus plumbing

`FieldLabel` is content inside the form pane's group, so `ctx.owner_active()` in
its `draw` reports form-pane focus. Changes:

- Remove the `focused: bool` field, the `set_focused()` method, and the
  `FieldLabel::new` initialisation of `focused`.
- In `draw`, replace every `self.focused` with `ctx.owner_active()`.
- Remove the call sites in `FormPane` that push focus onto every label each draw
  (the per-draw `set_focused` loop).
- **Keep** the `active` field, `set_active()`, and the selected-field chip logic
  — that is edaptor state (which field is current), not focus.

### 4. Pane backgrounds → `Group::set_surface`

- `TreePane` and `FormPane`: call
  `self.group.set_surface(Role::ListNormal, Role::ListInactive)` once at
  construction, and **delete** the focused-keyed `ctx.fill(extent, ...)`
  background block from each `draw` (`tree.rs:~227-234`, `form.rs:~662-668`). The
  group paints its own background before children (painter's algorithm, so the
  existing children still overpaint it).
- `form.rs` has a *second* fill at `form.rs:573/605` using a constant
  `ListNormalInactive` (→ `ListInactive`) surface — this is a separate,
  non-focus-keyed sub-region fill, not the pane background. The plan must inspect
  it: keep it (rename only) if it fills a genuine sub-region the surface does not
  cover; fold it into `set_surface` only if it is redundant. Default: keep +
  rename.
- Net: no edaptor pane `draw` selects a surface role from `self.group.focused`.

## Testing

- **Role renames** propagate into the existing highlight tests
  (`field_label.rs`, `tree.rs`, `leaf.rs`, `form.rs`). Every `Role::ListNormalActive`
  / `Role::ListNormalInactive` / `Role::OutlineNormalInactive` / `Role::InputPassive`
  in a test becomes its renamed form.
- **`field_label.rs` tests** currently drive brightness via `set_focused(true/false)`.
  Since that method is removed, they must drive the real signal instead: construct
  the test `DrawCtx` and call `DrawCtx::set_owner_active(bool)` before `draw`, then
  assert the same bright-vs-dim / chip outcomes. The `set_active` (selected chip)
  assertions are unchanged.
- **`tree.rs` / `leaf.rs` dimming tests** that set `pane.group.state.focused` and
  read a row background: the outline/list now dim via `owner_active`, which is
  fanned by `Group::draw`. Tests that call the pane's `draw` through the group
  still exercise the real path; tests that poked a child's `focused`/`active`
  directly must be updated to the `owner_active` path (drive focus on the pane
  group and let `draw` fan it, or set `owner_active` on the child's `DrawCtx`).
- A **new `set_surface` behaviour** is covered upstream in tvision-rs; edaptor
  needs a test only that its panes *recede as a whole* when unfocused — fold this
  into the existing pane dimming tests rather than adding a bespoke one.
- `make check` green (fmt + clippy `-D warnings` + tests). Cap parallelism at 4
  cores.
- **Manual TUI smoke** (demo server): confirm (a) the unfocused panes recede as a
  unit, (b) the focused pane's current row / selected-field chip still shows
  bright, and (c) no uncovered/black gaps appear in any pane after the fill moved
  into the framework.

## Docs / changelog

- **`CHANGES.md`**: entry under the unreleased section — upgraded to tvision-rs
  0.7; focus dimming is now driven by the framework (`owner_active` +
  `Group::set_surface`), removing edaptor's manual focus-mirroring and per-pane
  background fills. Note the role renames are internal (no user-visible or
  config change).
- **README / mdBook**: no change (internal rendering detail).

## Out of scope / non-goals

- No visual redesign — the rendered result must match today's focused/unfocused
  appearance (bright active pane, receded inactive panes, blue current-row /
  selected-field chip). This is a simplification, not a restyle.
- No change to the picker/shuttle migration already on this branch.
- No change to theme *colours* — only role *names* move.
- The `form.rs:573/605` secondary fill is renamed, not redesigned, unless the
  plan finds it strictly redundant.
